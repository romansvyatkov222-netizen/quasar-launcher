# Выпуск новой версии лаунчера (реальные сценарии)

Весь цикл: поднял версию → тег → GitHub Actions собрал → у игроков модалка
обновления (обязательная, без кнопки «Позже»).

---

## Сценарий A: менял ТОЛЬКО лаунчер (дизайн, поведение, фикс)

Бэкенд не трогаешь вообще.

1. Подними версию в `launcher/src-tauri/Cargo.toml`:
   ```toml
   version = "0.3.0"   # была 0.2.0
   ```
2. Закоммить, тегируй, пушь:
   ```bash
   git add -A
   git commit -m "v0.3.0: что изменилось"
   git tag v0.3.0
   git push origin main v0.3.0
   ```
3. Жди сборку (~7–10 мин, смотреть: github.com → репозиторий → Actions).
4. Всё. У игроков при следующем запуске — модалка «Требуется обновление».

## Сценарий B: менял ЛАУНЧЕР + БЭКЕНД (обычный случай)

Порядок важен: **сначала бэкенд, потом тег**. Старые лаунчеры продолжают
работать с новым бэкендом (контракт API не ломаем), новые игроки получают
новую версию.

1. **Обнови бэкенд на VDS:**
   ```powershell
   # из папки backend/
   npm run build
   tar -czf - src dist package.json prisma | ssh root@139.100.234.146 "tar -xzf - -C /home/quasar-backend && systemctl restart quasar-backend"
   ```
   Проверь, что сервис живой: `systemctl is-active quasar-backend` и
   `curl http://139.100.234.146:3000/api/health`.

2. **Подними версию лаунчера** (`Cargo.toml`, шаг из сценария A).

3. **Закоммить ВСЁ (лаунчер + бэкенд), тегируй, пушь:**
   ```bash
   git add -A
   git commit -m "v0.3.0: лаунчер + бэкенд"
   git tag v0.3.0
   git push origin main v0.3.0
   ```

## Сценарий C: менял ТОЛЬКО бэкенд

Тег и версию лаунчера **не трогаем**:
```bash
# сборка + деплой (шаг 1 из сценария B) — и всё
git add backend/ && git commit -m "бэкенд: ..." && git push origin main
```

---

## Как это выглядит у игрока

При следующем запуске лаунчера — модалка **«Требуется обновление»** без
кнопки «Позже»: игра в старую версию не пустит, пока не обновится.
После «Обновить» — прогресс, автозамена exe, автоперезапуск уже новой версии.

## Если сборка упала (красный крестик в Actions)

Тег перевыпускается:
```bash
git tag -d v0.3.0
git push origin :refs/tags/v0.3.0
# ...исправил...
git tag v0.3.0
git push origin v0.3.0
```

## Проверка после релиза

- github.com → Releases: там появился новый exe
- Запусти свой лаунчер: если твоя версия старее — увидишь модалку сам
- `curl http://139.100.234.146:3000/api/launcher/latest` → должен вернуть
  новую версию
